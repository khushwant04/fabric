# Operator and Deployment Design

**Status:** Planned — no CRD, operator, manifests, or bootstrap scripts are implemented.

## Responsibility

The Fabric operator is a narrow, cluster-local inference reconciler. It does not run benchmark experiments, authenticate end users, place workloads globally, meter invoices, or proxy inference.

## MVP API

`FabricModelDeployment` is the only Fabric CRD required for MVP. The exact versioned schema will be defined with the implementation; the intended shape is:

```yaml
apiVersion: inference.fabric.ai/v1alpha1
kind: FabricModelDeployment
metadata:
  name: qwen35-2b
spec:
  model:
    id: qwen3.5-2b
    revision: <immutable-revision>
  runtime:
    image: <registry>/<image>@sha256:<digest>
    dtype: fp16
    kernelMode: auto
  replicas: 1
  resources:
    gpuCount: 1
    gpuClass: t4
  limits:
    maxContextTokens: 32768
    maxOutputTokens: 2048
    maxConcurrency: 16
  rollout:
    strategy: Canary
status:
  observedGeneration: 1
  readyReplicas: 1
  endpoint: https://...
  conditions: []
```

Fields that cannot be implemented and validated in the first controller must not be added speculatively.

## Reconciled resources

The operator is planned to own:

- Deployment or equivalent workload.
- ClusterIP Service.
- ConfigMap and references to Secrets.
- ServiceAccount and least-privilege RBAC.
- GPU requests, node selectors, tolerations, and affinity.
- NetworkPolicy.
- PodDisruptionBudget where the stamp can satisfy it.
- Probes, lifecycle hooks, and graceful termination.
- Rollout metadata and status conditions.

Ingress and route objects may be generated by the operator or a separate platform controller, but route activation must depend on deployment readiness and local authorization configuration.

## Reconciliation contract

1. Validate model, image digest, GPU profile, dtype, and limits.
2. Reject unsupported combinations with a durable condition.
3. Reconcile immutable workload configuration from desired intent.
4. Wait for model load, runtime readiness, and authorization/route convergence.
5. Publish observed generation, replica counts, endpoint, and conditions.
6. Drain and roll forward or restore the last healthy revision on failure.
7. Use owner references/finalizers only for resources the operator must manage safely.

The controller must be idempotent and tolerate restart, duplicate events, stale status, and temporary control-plane disconnection.

## Stamp profiles

### Production T4 AKS

- One T4 and one model replica per pod.
- FP16 runtime profile.
- Multiple replicas/nodes for availability as capacity permits.
- Production release gate and cost/SLO evidence.

### A10 GPU VM/k3s

- Initially use Docker plus NVIDIA Container Toolkit for manual research benchmarks.
- Later install single-node k3s, NVIDIA device plugin, GPU Feature Discovery, and Fabric operator.
- Default production-style test is two one-GPU replicas on a two-A10 host.
- Optional tensor-parallel two is research-only.

### Single-node caveat

A one-node k3s stamp is one failure domain. A PodDisruptionBudget cannot create host availability. Higher availability requires additional nodes or a separate stamp.

## Planned VM scripts

```text
01-provision-vm
02-bootstrap-gpu
03-install-k3s
04-install-nvidia-components
05-install-fabric-operator
06-deploy-runtime
07-verify
99-destroy
```

Scripts must be idempotent where practical, pin versions, avoid embedding secrets, emit environment metadata, and make destructive cleanup explicit.

## Benchmark separation

Research benchmarks are invoked manually against immutable images and model revisions. The operator may deploy a production-style runtime for an operational smoke test, but it does not choose kernel parameters, execute benchmark matrices, or publish paper results.

## Rollout safety

- Image digest and model revision are immutable.
- Readiness includes model load and runtime self-test.
- Old replicas remain until replacements are ready where capacity permits.
- Streaming requests receive a drain window.
- Canary health uses latency, error, OOM, and correctness smoke signals.
- Rollback restores the last healthy configuration without requiring central services to serve requests.
